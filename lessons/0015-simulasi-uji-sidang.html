Simulasi Ujian Sidang Skripsi

30 pertanyaan kritis. Baca pertanyaan, jawab dari ingatan, lalu buka jawaban.

POC-ABS Teori & Implementasi

1. Jelaskan perbedaan mendasar antara POC-FS (Full Search) dan POC-ABS (All Block Search). Mengapa POC-ABS lebih cepat?
Jawaban: POC-FS mencari kecocokan block ke banyak kandidat posisi dalam search window. POC-ABS hanya membandingkan block di posisi yang sama antara frame referensi dan frame pembanding. Karena tidak perlu mengevaluasi banyak kandidat, POC-ABS jauh lebih ringan secara komputasi.
2. Dalam POC, kenapa yang dipakai adalah fase saja, bukan magnitude juga? Apa yang terjadi kalau pakai keduanya?
Jawaban: Fase menyimpan informasi posisi/struktur pola. Pergeseran gambar terbaca dari perubahan fase. Kalau pakai magnitude juga, pencocokan jadi lebih sensitif terhadap perbedaan kecerahan/kontras, bukan pergeseran geometris. POC membuang magnitude agar fokus pada pergeseran posisi.
3. Apa yang dimaksud dengan "puncak korelasi" pada POC? Jelaskan hubungannya dengan motion vector.
Jawaban: Puncak korelasi = titik tertinggi pada peta hasil POC. Posisi puncak dari titik tengah (0,0) menunjukkan arah dan besar pergeseran block. Dari posisi puncak ini dihitung X dan Y, yang menjadi motion vector.
4. Mengapa ukuran block mempengaruhi akurasi? Jelaskan hubungan block size 5x5 vs 25x25 dengan deteksi micro-expression.
Jawaban: Block lebih kecil (5x5) mendeteksi pergeseran lebih halus karena area perbandingan sempit. Block besar (25x25) melewatkan gerakan kecil karena pergeseran minor terdistribusi ke area luas. Paper Rosiani et al. menunjukkan 5x5 mencapai akurasi tertinggi (95.6% KNN, 94.3% SVM).
5. Di kode kamu, POC menerima dua input grayscale. Mengapa grayscale, bukan RGB?
Jawaban: POC bekerja pada domain frekuensi Fourier 2D. Grayscale = 1 channel, cukup untuk mendeteksi pergeseran pola. RGB = 3 channel, menambah komputasi 3× lipat tanpa manfaat signifikan untuk pencocokan posisi pola.

FAISS Similarity Search

6. FAISS digunakan di TABR untuk apa tepatnya? Jelaskan input dan output FAISS dalam konteks TABR.
Jawaban: FAISS mencari k-nearest neighbor dari vektor query di antara kandidat. Input: vektor query k (representasi input) dan candidate_k (representasi semua data train). Output: distances (jarak) dan context_idx (indeks tetangga terdekat).
7. Apa itu IndexFlatL2? Kenapa TABR memilih index ini, bukan index approximate seperti IVF atau HNSW?
Jawaban: IndexFlatL2 = exact brute-force L2 search. Tidak butuh training index, hasilnya tepat 100%. Untuk dataset kecil-medium seperti skripsi, flat search sudah cukup cepat. Index approximate (IVF, HNSW) baru dibutuhkan untuk dataset jutaan vektor.
8. Dalam kode TABR, self.search_index.reset() dipanggil sebelum add(). Kenapa?
Jawaban: Karena representasi kandidat berubah setiap training step (encoder masih belajar). Index harus diisi ulang dengan candidate_k terbaru. Kalau tidak di-reset, index berisi vektor kandidat versi lama.
9. Saat training, mengapa data input sendiri harus dibuang dari hasil pencarian FAISS?
Jawaban: Mencegah data leakage. Jika input menemukan dirinya sendiri sebagai tetangga terdekat, model bisa "mencontek" label sendiri tanpa benar-benar belajar dari data lain. Kode: jarak ke diri sendiri di-set inf, lalu dibuang.
10. Jika dataset train hanya 100 sampel, apakah FAISS masih dibutuhkan? Mengapa?
Jawaban: Untuk 100 sampel, pencarian brute-force sangat cepat (< 1ms). FAISS tetap dipakai karena kode dirancang umum, tapi bottleneck sebenarnya bukan di FAISS, melainkan di encoding kandidat.

TABR Arsitektur & Retrieval

11. Jelaskan alur lengkap TABR dari input sampai output. Sebutkan semua komponen utama.
Jawaban: Input → Encoder → representasi laten x → key k → FAISS search → context_idx → ambil label tetangga + hitung beda representasi → context_x → residual add x = x + context_x → Predictor (blocks + head) → output logits → softmax → prediksi kelas.
12. Apa bedanya encoder dan predictor dalam TABR? Kenapa tidak digabung jadi satu?
Jawaban: Encoder mengubah fitur mentah jadi representasi laten. Predictor mengubah representasi final (setelah context ditambahkan) jadi skor kelas. Dipisah karena encoder bekerja sebelum retrieval, predictor bekerja setelah retrieval + residual add.
13. Apa itu "residual add" di TABR (x = x + context_x)? Mengapa bukan x = context_x?
Jawaban: Residual add = menambahkan informasi baru ke informasi lama tanpa membuang lama. Kalau x = context_x, informasi asli input hilang total. Dengan residual, identitas input tetap ada, diperkaya oleh context.
14. Dalam TABR, context dibentuk dari label tetangga dan selisih representasi (k - context_k). Apa makna k - context_k?
Jawaban: Selisih antara representasi input dan representasi tetangga. Ini memberi tahu model: "seberapa berbeda input ini dari tetangganya". Makin kecil selisih, makin mirip. Makin besar, makin berbeda.
15. Apa yang terjadi jika context_size di-set terlalu besar (misal 50)? Apa risikonya?
Jawaban: Terlalu banyak tetangga, termasuk yang tidak mirip. Context jadi noisy. Bobot kemiripan (probs) menyebar ke banyak tetangga, termasuk yang tidak relevan. Akurasi bisa turun karena signal tenggelam dalam noise.

SPOTTING Onset–Apex–Offset

16. Jelaskan alur spotting dari magnitude mentah sampai output onset-apex-offset. Sebutkan semua tahapan.
Jawaban: Magnitude mentah → smoothing (Savitzky-Golay) → threshold (mean + std) → peak detection (apex) → phase boundary (onset/offset dari valley + cutoff) → duration filtering → output frame onset-apex-offset.
17. Mengapa threshold menggunakan mean + std, bukan hanya mean?
Jawaban: Mean saja terlalu rendah, banyak noise akan lolos. Mean + std memastikan peak harus lebih tinggi dari level normal DAN lebih tinggi dari variasi noise. Ini menaikkan spesifitas deteksi.
18. Apa bedanya height threshold dan prominence threshold dalam deteksi apex?
Jawaban: Height = puncak harus setinggi X. Prominence = puncak harus menonjol dari lembah sekitar. Peak bisa tinggi tapi kurang menonjol (prominence kecil), atau menonjol tapi tidak terlalu tinggi. Keduanya harus terpenuhi.
19. Dalam ApexPhase.find_phase(), bagaimana onset dan offset ditentukan? Jelaskan two-pass approach.
Jawaban: Pass 1: dari apex jalan ke kiri/kanan cari local valley (titik terendah). Pass 2: dari valley, hitung threshold = local_min + (apex - local_min) × cutoff_ratio. Onset = titik pertama dari apex ke kiri yang ≤ threshold. Offset = titik pertama dari apex ke kanan yang ≤ threshold.
20. Mengapa sinyal index perlu dikonversi ke frame index (+1)?
Jawaban: Magnitude index 0 berasal dari perbandingan frame[0] → frame[1], jadi representasi gerakan pada frame 1. Maka frame_index = signal_index + 1.

SAVGOL Savitzky-Golay Filter

21. Apa yang dilakukan Savitzky-Golay? Jelaskan dalam satu kalimat tanpa istilah teknis.
Jawaban: Savitzky-Golay menghaluskan sinyal dengan menggeser kurva kecil ke setiap titik, sehingga noise berkurang tapi bentuk puncak masih terjaga.
22. Mengapa Savitzky-Golay dipilih, bukan simple moving average? Apa keunggulan utamanya?
Jawaban: Moving average meratakan puncak. Savitzky-Golay fitting polynomial lokal sehingga bentuk peak lebih terjaga. Untuk spotting, mempertahankan bentuk peak sangat penting karena apex dicari dari peak.
23. Apa yang terjadi jika window_length terlalu besar? Dan jika terlalu kecil?
Jawaban: Terlalu besar: peak jadi gepeng, onset/offset melebar, apex salah. Terlalu kecil: noise masih banyak, peak palsu muncul.
24. Kenapa window_length harus ganjil?
Jawaban: Karena filter butuh satu titik tengah yang jelas untuk diganti nilainya. Window genap tidak punya satu titik tengah pasti.
25. Apa bedanya polyorder=2 dan polyorder=4? Kapan pakai mana?
Jawaban: Polyorder 2 = kurva kuadrat, lebih kaku, cocok untuk window kecil. Polyorder 4 = lebih fleksibel, bisa mengikuti bentuk kompleks, cocok untuk window besar. Terlalu tinggi bisa mengikuti noise.

INTEGRASI Hubungan Antar Komponen

26. Jelaskan alur lengkap dari frame mentah CASME sampai output prediksi anxiety. Sebutkan semua komponen: POC-ABS, spotting, FAISS, TABR.
Jawaban: Frame → ROI extraction → POC-ABS per block → magnitude per ROI → mean magnitude per frame-pair → magnitude signal → smoothing → threshold → apex detection → phase boundary → event onset-apex-offset → fitur event → TABR: encoder → latent → FAISS search tetangga → context → residual add → predictor → output anxiety tinggi/rendah.
27. Jika smoothing dihapus, apa dampaknya ke seluruh pipeline?
Jawaban: Noise meningkat → peak palsu banyak → apex salah → onset/offset tidak akurat → fitur event buruk → prediksi TABR tidak akurat.
28. Mengapa 3 ROI (mata-alis kanan, mata-alis kiri, mulut) dirata-ratakan menjadi satu nilai? Bukan diproses terpisah?
Jawaban: Untuk spotting: perlu satu sinyal ringkas yang mewakili gerakan wajah secara keseluruhan. Rata-rata memberi gambaran umum kekuatan gerak. Untuk TABR: fitur per ROI bisa dipakai sebagai input terpisah, tergantung desain eksperimen.
29. Apa kelemahan utama pendekatan POC-ABS untuk micro-expression spotting?
Jawaban: (1) Hanya mendeteksi translasi, bukan rotasi/deformasi. (2) Sensitif terhadap perubahan pencahayaan. (3) Membutuhkan landmark wajah yang stabil. (4) Block matching bisa melewatkan gerakan non-translational.
30. Jika ditanya penguji: "Mengapa tidak pakai optical flow saja?", apa jawaban kamu?
Jawaban: Optical flow lebih akurat untuk gerakan kompleks, tapi komputasinya berat dan kurang praktis untuk real-time. POC-ABS lebih ringan (0.03 detik/frame vs 0.236 detik/frame untuk POC-FS). Untuk micro-expression yang butuh kecepatan, POC-ABS cukup kompetitif dengan akurasi 95.6%.
